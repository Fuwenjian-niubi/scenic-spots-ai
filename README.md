# 景点讲解 AI（直连版）

> 面向游客的实时景点讲解系统：流式文本 + 语音播报，RAG 检索增强问答。中文原生、低延迟、零第三方依赖。

本项目采用**直连式架构**：`web/server.py` 直接调用智谱 embedding-3 做向量化、DeepSeek 做流式问答、本地余弦检索，**仅需 Python 标准库即可运行**——无 Docker、无 Ollama、无向量数据库，一条命令启动。

## 技术架构

```
┌─────────────────────────── 前端 web/index.html ───────────────────────────┐
│  三栏布局 · 流式渲染(200ms 节流) · Web Speech 语音 · 设置抽屉 · 响应式      │
└────────────────────────────────┬──────────────────────────────────────────┘
                                 │ SSE (text/event-stream)
┌────────────────────────────────▼──────────────────────────────────────────┐
│                        后端 web/server.py（纯标准库）                       │
│  ┌─────────┐  ┌─────────┐  ┌──────────────────────────────────────────┐  │
│  │storage  │  │ crypto  │  │  rag.py                                   │  │
│  │路径/JSON│  │密钥加密  │  │  嵌入(智谱) · 余弦检索 · 名称加权 · 分块     │  │
│  │上传管理 │  │PBKDF2   │  │  LRU语义缓存 · DeepSeek流式 · 向量原子操作    │  │
│  └─────────┘  └─────────┘  └──────────────────────────────────────────┘  │
│                           ┌────────────┐  ┌─────────────────────┐       │
│                           │extract.py  │  │.vector_cache.pkl    │       │
│                           │docx/pdf提取│  │向量磁盘缓存(增量)    │       │
│                           └────────────┘  └─────────────────────┘       │
└────────────────────────────────┬──────────────────────────────────────────┘
                                 │
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
       DeepSeek API         智谱 API          知识库文档
       deepseek-chat        embedding-3       sample-data/ + uploads/
       （流式问答）           （向量化）         （## 景点名 + 固定字段）
```

**数据流**：游客提问 → 问题向量化 → 本地余弦检索 Top-4（名称加权 + 阈值 0.35）→ 拼装上下文 Prompt → DeepSeek 流式生成 → SSE 转发 → 前端渲染 + 语音播报。

**设计要点**：
- **零依赖**：HTTP 用 `http.server`、嵌入/聊天用 `urllib`、缓存用 `pickle`，全部标准库，`pip install` 都不需要
- **增量嵌入**：只对新文档/变更文件重新向量化，重启秒加载
- **并发安全**：向量库读写通过 `vector_add / vector_remove / vector_snapshot` 原子操作（RLock）

## 快速开始

```bash
# 1. 申请两个 Key：
#    DEEPSEEK_API_KEY   https://platform.deepseek.com
#    ZHIPU_API_KEY      https://open.bigmodel.cn   (智谱 embedding-3)
cp .env.example .env   # 填入两个 Key

# 2. 启动（二选一）
python web/server.py        # 命令行启动
# 或双击 start.bat          # Windows 后台运行：pythonw 启动，日志写 server_run.log，
                            # 关闭弹出的黑窗口不会停止服务；停止服务请结束 pythonw.exe

# 3. 浏览器打开 http://127.0.0.1:8080
```

> 不填 Key 也能打开网页浏览界面（自动进入演示模式，含 3 个示例景点），但真实讲解需配置 Key——环境变量（`.env`）或网页「设置 → 账号」录入（加密存储）。

## 使用指南

### 游客视角

1. **选景点**：左侧景点列表点击任意景点 → 自动发起讲解
2. **追问**：对话框直接输入问题（如"门票多少钱""怎么去"），支持多轮对话
3. **快捷提问**：选中景点后点「怎么去 / 门票多少 / 开放时间 / 推荐看点」芯片
4. **语音播报**：顶部「语音播报」开关，回答完成后自动朗读；语速/音量/音色在设置中调整
5. **来源引用**：回答下方显示「来源：xxx」，来自知识库检索命中

### 管理员视角（设置抽屉）

| 设置项 | 位置 | 说明 |
|---|---|---|
| API Key | 设置 → 账号 | DeepSeek / 智谱 Key，加密存储，可清除 |
| 语音 | 设置 → 通知 | 语速 0.5–3.0、音量、音色、试听 |
| 外观 | 设置 → 外观 | 浅色/深色/跟随系统、正文字号 |
| 隐私 | 设置 → 隐私 | 清空对话、清除本地缓存 |
| 知识库 | 设置 → 通用 | 新建景点、上传文档、删除景点、默认景点、每景点切分设置 |

### 知识库管理

- **新建景点**：设置 → 通用 → 输入景点名 → 「＋ 新建」
- **上传文档**：景点文件夹内「＋ 上传文档」，支持 md / docx / pdf / 常见图片（单文件 ≤20MB）
  - `.md`：按 `## 景点名` 标题解析为多个景点条目；无标题则整文件归属一个景点
  - `.docx` / `.pdf`：纯标准库提取文本 → 分块向量化（扫描件 PDF 会提示"无法提取文本"）
  - 图片（≤8MB）：**自动调用免费视觉模型 glm-4v-flash 识别内容**——提取图中文字（票价/时间/介绍）+ 内容描述，分块向量化后可直接检索；识别失败自动降级为文件名标签
- **删除**：上传文件硬删除；内置 sample 文件软删除（可恢复）
- **切分设置**：长文档按「最大段字符数」切成多段分别向量化，保存后立即重嵌该景点

## 核心选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 嵌入模型 | **智谱 embedding-3**（云端） | 中文原生，2048 维，无需本地 Ollama |
| 聊天模型 | **deepseek-chat**（云端） | 中文强 + 流式快 + 极低成本 |
| 检索 | **本地余弦检索 Top-4 + 名称加权** | 景点库小，无需独立向量服务；查询含景点名时相似度 +0.15 |
| 向量缓存 | **磁盘 pickle + 增量嵌入** | 新增文档才重新向量化，重启秒加载 |
| 分块 | 500~800 字符 / 50 重叠（每景点可独立配置） | 按景点条目语义切分 |
| 流式 | DeepSeek stream + SSE + 前端 200ms 节流 | 首字即回传，读屏友好 |
| 缓存 | LRU 语义响应缓存（256 条） | 高频问题（门票/开放时间）免调用 LLM |
| 文本提取 | 纯标准库（docx zip+xml / pdf 文本流） | 保持零依赖 |
| 图片识别 | **智谱 glm-4v-flash**（免费视觉模型） | 复用智谱 Key，识别图中文字与内容后入库 |

## 知识库文档格式

每个景点一个 `## 景点名` 块，固定字段：

```
## 广州塔
名称：广州塔，又称"小蛮腰"。
简介：...
历史：...
文化：...
看点：...
交通：...
开放时间：...
门票：...
贴士：...
```

- 字段名固定，便于向量语义对齐与前端简介提取
- 修改 `sample-data/` 后重启服务自动增量嵌入；切分配置变化自动全量重嵌
- 新增景点：直接新建 `## 景点名` 块，或网页端「新建景点 + 上传文档」

## 效果评测

> 评测方法、逐题明细与已知缺陷详见 [`eval/REPORT.md`](eval/REPORT.md)。

**评测集**：`eval/questions.json`，29 题 = 27 题库内（11 个在册景点 × 门票/开放时间/交通/看点/历史/简介/文化）+ 2 条库外负样本（期望被阈值拒绝，防答非所问）。

**当前结果**（2026-08-19，DeepSeek + embedding-3 实测 3 轮）：

| 指标 | 3 轮均值 | 说明 |
|---|---|---|
| 检索 Recall@4 | **100%** | 期望景点进入 Top-4（27/27） |
| 阈值命中率 | **100%** | 期望景点通过相似度阈值（0.35） |
| Top1 命中率 | **100%** | 期望景点排名第一 |
| 库外问题拒绝率 | **100%** | 库外问题被正确拒绝（2/2） |
| 问答严格通过率 | **~65%** | 答案含全部期望关键词（自动初判，偏严） |
| 问答基本正确率 | **~90%** | PASS + PARTIAL（答案主体正确） |
| 平均相似度 | 0.60 | 名称加权后相对基线（0.46）提升 30% |

**评测驱动的系统改进**（已落地）：
1. **名称命中加权**：查询含景点名 → 该景点条目相似度 +0.15，修正向量相似度绝对值偏低问题
2. **系统提示词强化数字忠实度**：门票类回答须引用资料确切数字，缓解 LLM 数字幻觉（如长隆"约 300 元"曾被编成"350/280 元"）

**已知缺陷**（如实记录）：门票类问答的 LLM 数字幻觉已缓解未根除；自动判定为关键词口径，存在口语化改写漏判——答辩前建议人工复核 `eval/results/round1.csv`。

## 安全说明

| 项 | 状态 |
|---|---|
| API Key 存储 | PBKDF2(120k) + HMAC-SHA256 认证加密，落盘非明文（`web/.api_config.json`） |
| 密钥显示 | 脱敏（仅显示首 6 尾 4） |
| 历史消息 | 后端裁剪（≤12 轮、单条 ≤4000 字符、过滤非法 role），防提示注入与超长请求 |
| 文件上传 | 扩展名白名单、单文件 20MB、目录总量 500MB、文件名消毒、路径穿越防护 |
| 前端 | 动态内容统一 `esc()` 转义，防 XSS；无障碍（读屏标题/减弱动态效果） |
| 网络 | 默认仅监听 `127.0.0.1`；`--host 0.0.0.0` 时**所有接口无鉴权**，严禁公网暴露 |

> ⚠️ 本项目定位为**单机/局域网个人部署**，不含用户账号体系。若需公网多用户，需自行加鉴权层。

## 常见问题

**Q：不填 Key 能用吗？**
能浏览界面与演示模式（3 个示例景点本地数据），但真实讲解需配置 Key。

**Q：上传 PDF 后问不到内容？**
仅"文本型 PDF"（有文字层）能提取；扫描件/图片型 PDF 无文本层，上传时会明确提示。图片（≤8MB）会自动调用免费视觉模型识别图中文字与内容。

**Q：上传的图片能识别吗？**
能。图片上传后自动调智谱 glm-4v-flash（免费）提取图中文字（如票价、开放时间）与内容描述，分块向量化后可直接检索；超过 8MB 或识别失败会降级为文件名标签并在前端提示。

**Q：问库外的问题（如"巴黎铁塔门票"）会怎样？**
检索相似度低于阈值 0.35 被拒绝，返回引导提示而非胡编——这是有意的防幻觉设计。

**Q：改了 sample-data 文档不生效？**
重启服务触发增量嵌入；或改动后删除 `web/.vector_cache.pkl` 强制全量重建。

**Q：如何局域网共享？**
`python web/server.py --host 0.0.0.0`，需自行保障网络环境可信。

**Q：Windows 双击 start.bat 后黑窗口能关吗？**
能。服务由 `pythonw.exe` 后台运行（日志在 `server_run.log`），停止服务需结束 `pythonw.exe`。
