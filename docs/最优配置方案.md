# 景点讲解 AI · 方案说明（直连版）

> 目标：低延迟、高准确度的实时景点语音/文本讲解。核心指标：首字延迟(TTFT) < 1s，问答准确率 > 90%，知识库加载速度高。
> 本文档与 `web/` 实际实现完全对齐（embedding-3 + DeepSeek + 本地余弦检索，纯标准库、零第三方依赖）。

## 一、总体架构

```
[游客终端]──文本提问──┐
                      ├──> [web/server.py]──① 问题向量化(智谱 embedding-3)
[游客终端]──语音播报──┘         │       ② 本地余弦检索 Top-4(名称加权 + 阈值 0.35)
                                │       ③ 拼装 Prompt → DeepSeek 流式生成
                                └────── [SSE 流式文本] → [前端渲染 + 语音朗读]
[景点知识库 sample-data/]──增量嵌入──> [向量磁盘缓存 .vector_cache.pkl]
```

数据流五步：**问题 → 向量化 → 检索 → 上下文拼装 → 流式生成**。低延迟的关键：聊天走 DeepSeek 流式（首字即回传）、检索走本地内存余弦（<20ms）、重复请求走语义缓存（免调用 LLM）。

## 二、模型选型（结论先行）

### 1. 嵌入模型：智谱 embedding-3（选用）

| 候选 | 中文效果 | 向量维度 | 本地/云端 | 结论 |
|---|---|---|---|---|
| **embedding-3**（智谱） | 强，中文原生 | 2048 | 云端 API | ✅ **选用** |
| bge-m3 | MTEB 中文 Top2 | 1024 | 本地 Ollama | 备选，需本地跑 |
| text-embedding-3-large | 好 | 3072 | 云端(OpenAI) | 备选 |
| nomic-embed-text | 偏英文 | 768 | 本地 | ❌ 中文弱 |

**理由**：全云端方案——聊天走 DeepSeek、嵌入走智谱 embedding-3，**无需本地 Ollama**。景点讲解是纯中文语义检索，中文原生模型对「景点名/历史人物/典故」这类专有名词召回率更高。

> 关键原则：**嵌入模型必须用专门的嵌入模型，不能用聊天模型当嵌入模型**——这是检索效果差的头号原因。DeepSeek 无 embedding 接口，故嵌入用智谱 embedding-3。

### 2. 聊天大模型：云端 DeepSeek（选用）

| 方案 | 模型 | 首字延迟 | 中文质量 | 成本 | 适用 |
|---|---|---|---|---|---|
| **A 云端（选用）** | `deepseek-chat`（DeepSeek API） | < 0.5s | 强 | 极低 | 有网、极致速度 |
| A+ 深度思考 | `deepseek-reasoner` | 1~2s | 更强（推理） | 低 | 复杂历史典故问答 |
| B 本地（离线备选） | `qwen3:8b`（Ollama） | 0.5~2s（GPU） | 强 | 0 | 无网、隐私 |
| C 平衡 | GLM-4-Flash / Qwen(DashScope) | < 0.5s | 强 | 低 | 备选 |

**推荐策略**：选用**云端 DeepSeek**——中文强、流式快、按量计费极低。若需离线/隐私场景，替换 `web/rag.py` 中的 `DEEPSEEK_URL` 与模型名即可。

## 三、检索：本地余弦 + 名称加权（当前实现）

| 项 | 值 | 说明 |
|---|---|---|
| 检索方式 | 内存余弦暴力扫描 | 景点库数百条向量，O(N) 毫秒级，无需独立向量库 |
| Top-K | 4 | 每次召回片段数 |
| 相似度阈值 | 0.35 | 过滤低相关噪声；**库外问题（如问清华/巴黎）会被正确拒绝** |
| 名称加权 | 查询含景点名 → 相似度 +0.15 | 景点名是强信号，修正向量相似度绝对值偏低（0.3~0.6）的排序问题；对库外问题不生效 |

**评测数据**（2026-08-19，29 题 3 轮）：检索 Recall@4 / 阈值命中 / Top1 均为 **100%**，库外问题拒绝率 **100%**。详见 `eval/REPORT.md`。

## 四、分块策略（中文景点内容专用）

景点内容特点是「结构性强、条目独立」。最优策略是**按景点条目语义分块**，而非随机切分：

| 参数 | 推荐值 | 说明 |
|---|---|---|
| 分块大小 | **500~800 字符** | 一个景点/一个主题片段，过大语义混杂、过小上下文断裂 |
| 分块重叠 | **50 字符** | 保持跨块语义连贯 |
| 每景点独立配置 | 支持 | 设置 → 通用 → 每个景点「⚙ 切分设置」，保存后立即重嵌 |

**关键做法**：每个景点一个独立 Markdown 块，固定字段（名称/简介/历史/文化/看点/交通/开放时间/门票/贴士），让向量天然按语义对齐。示例见 `sample-data/景点示例.md`。

> ⚠️ 修改分块参数后必须重新嵌入才生效——系统会自动检测配置变化并全量重嵌（`load_or_build_cache`）。

## 五、流式输出（降低感知延迟）

1. **API 层**：DeepSeek `stream: true`，后端逐 delta 转发为 SSE（`data: {...}`），首字到达即回传。
2. **前端层**：200ms 节流刷新 DOM（避免读屏器逐字朗读）；渲染完毕后整段语音播报（Web Speech API，支持语速 0.5~3.0、音量、音色切换与试听；新回答打断旧播报）。
3. **容错**：检索不达阈值 → 引导提示；LLM 调用失败 → SSE error + 前端重试按钮；后端不可达 → 前端演示模式兜底。

## 六、缓存机制（多层，减少重复开销）

| 层级 | 机制 | 作用 |
|---|---|---|
| L1 语义响应缓存 | LRU（256 条），归一化去语气词 | 高频问题（开放时间/门票/交通）跳过 LLM，省 90% 开销 |
| L2 向量磁盘缓存 | pickle + 增量嵌入 + mtime 检测 | 只对新文档/变更文件重嵌，重启秒加载 |
| L3 切分配置快照 | 比对配置哈希 | 配置变化自动全量重嵌 |
| L4 前端缓存 | 收藏/主题/字号/默认景点 localStorage | 偏好持久化 |

**并发安全**：向量库读写走 `vector_add / vector_remove / vector_snapshot` 原子操作（RLock），上传/删除/重嵌与检索并发安全。

## 七、文档预处理优化（保证知识库加载迅速）

1. **统一为结构化 Markdown**：`## 景点名` + 固定字段，一处修改即重载。
2. **清洗**：去空白噪声、统一全角标点、去重复段落（`scripts/preprocess.py`）。
3. **多格式上传**：docx（zip+xml 提取 `<w:t>`）、pdf（文本流启发式解析；扫描件无文本层会提示）均纯标准库解析入库；图片记录文件名标签（不做 OCR）。

```bash
python scripts/preprocess.py 原始文档目录 -o sample-data
```

## 八、部署（当前主线：直连版，零依赖）

```bash
# 1. 申请两个 Key：
#    DEEPSEEK_API_KEY   https://platform.deepseek.com
#    ZHIPU_API_KEY      https://open.bigmodel.cn   (智谱 embedding-3)
cp .env.example .env   # 填入两个 Key

# 2. 启动
python web/server.py            # 命令行启动
# 或双击 start.bat             # Windows 后台运行，日志写 server_run.log

# 3. 浏览器打开 http://127.0.0.1:8080
```

> ⚠️ 服务默认仅监听 `127.0.0.1`。局域网访问用 `python web/server.py --host 0.0.0.0`，但**所有接口无鉴权**，请勿暴露到公网。
