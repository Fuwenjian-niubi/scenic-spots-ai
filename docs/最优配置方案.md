# 景点讲解 AI · AnythingLLM 最优配置方案

> 目标：低延迟、高准确度的实时景点语音/文本讲解。核心指标：首字延迟(TTFT) < 1s，问答准确率 > 90%，知识库加载速度高。

## 一、总体架构

```
[游客终端]──语音(STT)──┐
                      ├──> [AnythingLLM API]──流式──> [LLM 大模型] ──┐
[游客终端]──文本───────┘         │                                    │
                                │  ① 问题向量化(智谱 embedding-3)    ├──> [流式文本]
                                │  ② 向量检索(LanceDB)                │
                                │  ③ 取 Top-K 上下文                  └──> [TTS 流式语音]
                                │  ④ 拼装 Prompt → LLM 生成
[景点知识库]──预处理──> [向量库 LanceDB]
```

数据流四步：**问题 → 向量检索 → 上下文拼装 → 流式生成**。低延迟的关键在于聊天走流式 DeepSeek、检索走本地 LanceDB、重复请求走缓存。

## 二、模型选型（结论先行）

### 1. 嵌入模型：智谱 embedding-3（本项目选用）

| 候选 | 中文效果 | 向量维度 | 本地/云端 | 结论 |
|---|---|---|---|---|
| **embedding-3**（智谱） | 强，中文原生 | 2048 | 云端 API | ✅ **选用** |
| bge-m3 | MTEB 中文 Top2 | 1024 | 本地 Ollama | 备选，需本地跑 |
| text-embedding-3-large | 好 | 3072 | 云端(OpenAI) | 备选 |
| nomic-embed-text | 偏英文 | 768 | 本地 | ❌ 中文弱 |

**理由**：全云端方案——聊天走 DeepSeek、嵌入走智谱 embedding-3，**无需本地 Ollama**。智谱 embedding-3 中文原生支持、2048 维、检索准确度高，经 OpenAI 兼容接口（`generic-openai`）接入 AnythingLLM。景点讲解是纯中文语义检索，中文原生模型对「景点名/历史人物/典故」这类专有名词召回率更高。

### 2. 聊天大模型：云端 DeepSeek（本项目选用）

| 方案 | 模型 | 首字延迟 | 中文质量 | 成本 | 适用 |
|---|---|---|---|---|---|
| **A 云端（本项目选用）** | `deepseek-chat`（DeepSeek API） | < 0.5s | 强 | 极低 | 有网、极致速度 |
| A+ 深度思考 | `deepseek-reasoner` | 1~2s | 更强（推理） | 低 | 复杂历史典故问答 |
| B 本地（离线备选） | `qwen3:8b`（Ollama） | 0.5~2s（GPU） | 强 | 0 | 无网、隐私 |
| C 平衡 | GLM-4-Flash / Qwen(DashScope) | < 0.5s | 强 | 低 | 备选 |

**推荐策略**：本项目选用**云端 DeepSeek**——中文强、流式快、按量计费极低。若需离线/隐私场景，切回本地 `qwen3:8b`（改 docker-compose 一处即可）。

> 关键原则：**嵌入模型必须用专门的嵌入模型，不能用聊天模型当嵌入模型**——这是检索效果差的头号原因。本项目聊天用 DeepSeek（无 embedding 接口），嵌入用智谱 embedding-3（OpenAI 兼容）。

## 三、向量数据库：LanceDB（默认即最优）

| 候选 | 部署复杂度 | 检索延迟 | 适用规模 | 结论 |
|---|---|---|---|---|
| **LanceDB** | 零配置·内嵌 | 毫秒级·本地磁盘 | < 百万级向量 | ✅ **选用** |
| Qdrant / Milvus | 需独立服务 | 毫秒级 | 千万级+ | 景点库用不上 |
| Pinecone / Zilliz | 云端 | 受网络影响 | 海量 | ❌ 增加网络延迟 |

景点知识库规模（数百~数千条结构化条目）远低于需要独立向量库的量级。LanceDB 内嵌、本地 NVMe 直读、无网络往返，是低延迟场景的最优解。**唯一要求：storage 目录放 SSD（NVMe），可提升检索速度约 5 倍。**

## 四、分块策略（中文景点内容专用）

景点内容特点是「结构性强、条目独立」。最优策略是**预处理时按景点条目语义分块**，而非随机切分：

| 参数 | 推荐值 | 说明 |
|---|---|---|
| 分块大小 | **500~800 字符** | 一个景点/一个主题片段，过大语义混杂、过小上下文断裂 |
| 分块重叠 | **50 字符** | 保持跨块语义连贯 |
| 相似度阈值 | **0.3~0.5** | 过滤低相关噪声，提高准确度 |
| Top-K 检索 | **4~6** | 每次召回片段数 |

**关键做法**：每个景点一个独立 Markdown 块，固定字段（名称/历史/文化/看点/交通/开放时间/门票/贴士），让向量天然按语义对齐。示例见 `sample-data/景点示例.md`。

> ⚠️ 修改分块参数后必须重新嵌入所有文档才生效。

## 五、流式输出（降低感知延迟）

1. **API 层**：使用 `stream-chat` 端点（SSE），首字到达即回传，无需等完整生成。UI 默认已流式。
2. **语音层**：TTS 按句子流式合成（Edge-TTS 免费中文神经音色，zh-CN-YunxiNeural），第一句讲解在首字到达后即可开播。
3. 示例客户端见 `scripts/demo_chat.py`（文本）与 `scripts/demo_voice.py`（语音）。

## 六、缓存机制（多层，减少重复开销）

| 层级 | 机制 | 作用 |
|---|---|---|
| L1 语义响应缓存 | 高频问题(开放时间/门票/交通)缓存答案 | 相同/相似问题直接返回，跳过 LLM 调用，省 90% 开销 |
| L2 嵌入缓存 | 批量嵌入 + 高并发块 | 文档加载一次向量化，重复加载跳过 |
| L3 检索缓存 | LanceDB 本地索引 + 热点 Top-K 缓存 | 重复检索零开销 |
| L4 前端缓存 | 讲解稿预生成 + 本地缓存 | 离线可播，二次访问秒开 |

## 七、文档预处理优化（保证知识库加载迅速）

1. **统一为结构化 Markdown**：`## 景点名` + 固定字段，一处修改即重载。
2. **清洗**：去空白噪声、统一全角标点、去重复段落。
3. **OCR**：扫描件启用中文 OCR（`TARGET_OCR_LANG=chi_sim`）。
4. **按条目预分块**：预处理阶段切好语义块，AnythingLLM 直接索引，跳过重新切分。
5. **批量并发**：提高嵌入并发块数，加速批量加载。

预处理脚本：`scripts/preprocess.py`。

## 八、部署步骤

```bash
# 1. 申请两个 Key 并填入 deploy/docker-compose.yml:
#    - DEEPSEEK_API_KEY                    https://platform.deepseek.com
#    - GENERIC_OPEN_AI_EMBEDDING_API_KEY   https://open.bigmodel.cn (智谱)

# 2. 启动 AnythingLLM（Docker）
cd deploy
docker compose up -d

# 3. 访问 http://localhost:3001，用 AUTH_TOKEN 密码登录
#    （首次登录向导中 LLM/Embedding/向量库会自动读取环境变量）

# 4. 预处理景点文档
python scripts/preprocess.py 原始文档目录 -o sample-data

# 5. 上传到工作区 → 「保存并嵌入」→ 开始问答
```

## 八点五、Web 网页

本项目附带 Web 前端（`web/`），面向游客的景点讲解界面，支持流式文本 + 语音朗读：

```bash
# 启动后端(纯标准库,零第三方依赖)
python web/server.py
# 浏览器打开 http://localhost:8080
```

详情见 `web/` 目录与 `web/server.py` 顶部注释。

## 九、预期性能

| 指标 | 云端 DeepSeek（本项目） | 本地 Qwen3:8b(GPU) |
|---|---|---|
| 首字延迟 TTFT | < 0.5s | 0.5~2s |
| 单条问答 | 1~2s | 1~4s |
| 检索延迟 | < 20ms | < 20ms |
| 100 景点加载 | ~10~30s | ~10~30s |

## 十、参数速查表（环境变量）

| 变量 | 推荐值 | 作用 |
|---|---|---|
| `EMBEDDING_ENGINE` | `generic-openai` | 嵌入引擎(OpenAI 兼容) |
| `EMBEDDING_BASE_PATH` | `https://open.bigmodel.cn/api/paas/v4` | 智谱端点 |
| `EMBEDDING_MODEL_PREF` | `embedding-3` | 智谱嵌入模型 |
| `GENERIC_OPEN_AI_EMBEDDING_API_KEY` | `智谱 key` | 智谱密钥 |
| `EMBEDDING_MODEL_MAX_CHUNK_LENGTH` | `800` | 嵌入最大块长 |
| `LLM_PROVIDER` | `deepseek` | 聊天模型 |
| `DEEPSEEK_API_KEY` | `sk-xxx` | DeepSeek 密钥 |
| `DEEPSEEK_MODEL_PREF` | `deepseek-chat` | DeepSeek 模型 |
| `VECTOR_DB` | `lancedb` | 向量库 |
| `TARGET_OCR_LANG` | `chi_sim,eng` | OCR 语言 |
